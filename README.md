# StudyAssist (Schooly)

A curriculum-aware AI tutoring platform for Bulgarian school students. The AI is restricted to the material the student has already studied at their grade level, preventing it from answering questions outside the curriculum.

## Implementation Status

### Complete
- User authentication: login, register, logout, JWT access tokens + refresh tokens
- Password reset flow: 6-digit email code with 10-minute expiry, brute-force protection (5 attempts), and same-password check
- Progressive rate limiting: per-account and per-IP for login, per-email for registration and password reset; IP-based limit on token refresh and logout
- User roles: Student, Teacher, SchoolAdmin, Admin
- School entity management: `School` is a first-class entity (`Id`, `Name`, `CreatedAt`); `ApplicationUser`, `Class`, and `Subject` each reference it via a `SchoolId` int FK (no loose school-name strings); school creation via HTTP (`POST /api/global-admin/schools`); full CLI management via `AdminUserService`
- Class join codes: a SchoolAdmin can create a "blank" class already assigned to a teacher (`POST /api/admin/classes`); that teacher generates/regenerates a per-class `ClassJoinCode` (`GET/POST /api/teacher/classes/{classId}/join-code[/regenerate]`); a student who enters the code — either at registration (`POST /api/auth/register`'s optional `classJoinCode` field) or later via `POST /api/student/classes` — is attached to the class, its teacher, and its school in one step. A student can belong to more than one class (`ClassStudent` join table replaces the old single `ApplicationUser.ClassId` FK), but all of a student's classes must share one school. The code stays fully optional — a student who never enters one stays schoolless/classless, same as before this feature existed
- PDF ingestion pipeline: PdfPig plain-text extraction by default, with a selective Pix2Text formula-only OCR pass for pages embedding MathType/Equation-Editor fonts (vision OCR is a whole-document fallback used only when Pix2Text is unavailable); chunking is page-aware (`PDFLoader.ChunkPages`), so a chunk never spans two PDF pages and each chunk's Qdrant payload records its source page; embedding via `nomic-embed-text-v2-moe` with Nomic's `search_document:`/`search_query:` task prefix applied automatically (`EmbeddingService.GetDocumentEmbeddingsAsync`/`GetQueryEmbeddingsAsync`)
- Qdrant vector DB integration with grade-filtered semantic search
- Ollama local LLM chat service with streaming
- ZhipuAI remote LLM chat service with streaming (`ZhipuAIChatService`, implements the same `IChatService` interface as Ollama) — implemented but not currently registered in `Program.cs`; switching backends means editing that DI registration, there is no automatic runtime failover
- RAG orchestration: grade-filtered retrieval + LLM call with context injection
- Stereometry 3D scene JSON schema and `<STEREO>` block extraction from LLM responses
- Exam generation service: mock exams generated from curriculum material via RAG
- Chat message persistence with subject and topic tagging
- Chat sessions: messages are grouped into `ChatSession`s with true multi-turn context (prior turns are replayed into the LLM call, not just displayed), an AI-generated title after the first exchange, and a subject-folder assignment locked from that same first exchange
- Weak-spot detection: aggregates most-asked topics per student, exposed to the student themselves via `GET /api/student/weak-spots?days=N` (distinct from the teacher-facing per-class `GET /api/teacher/classes/{classId}/struggles`)
- Database schema: 16 migrations defined (PostgreSQL), most recent is `AddClassSubjectTagAndPersonalSubjects` (adds `Class.SubjectId`, makes `Subject.SchoolId` nullable for the personal/global fallback bucket, adds `ChatSession.ClassId`); previous is `ReplaceClassIdWithClassStudentJoinTable` (adds `ClassStudent`/`ClassJoinCode`, backfills existing single-class assignments, drops `ApplicationUser.ClassId`); run `dotnet ef database update` before starting the server
- Subject tags: every class is tagged with a school-scoped `Subject` at creation (`SubjectId`, required going forward — nullable only for pre-existing classes); a student's chat sessions are auto-filed under both a `Subject` folder and, when the resolved subject matches one of the student's classes, that class's `ClassId` too — both locked on the session's first exchange (`ChatSessionService.SetFolderAndTitleOnceAsync`) and re-filed off the class (not deleted) if a SchoolAdmin later removes that student from it. `SubjectResolutionService` get-or-creates the `Subject` row for whatever the LLM classifies a message's subject as, so chats are never left unfoldered for lack of a pre-existing `Subject` — schoolless students resolve into a personal/global fallback `Subject` bucket (`SchoolId = null`)
- Security hardening pass: TOCTOU-safe refresh token revocation, prompt injection sanitisation, generic rate limit error messages, HSTS, CORS header restriction, ForwardedHeaders middleware
- Student chat: `POST /api/chat/message` — grade-filtered RAG, SSE token streaming, stereometry scene extraction, session-scoped chat-log persistence with multi-turn context and AI-generated titles; `GET /api/chat/sessions?subject=` (folder-filterable session list), `GET /api/chat/sessions/{id}/messages` (session transcript) — all require auth, no role restriction
- PDF session upload: `POST /api/chat/upload` — ingests a PDF into a per-request temporary vector store that affects subsequent chat queries
- Teacher dashboard HTTP endpoints: `GET /api/teacher/classes`, `GET /api/teacher/classes/{classId}/struggles?days=N`, `GET /api/teacher/activity?days=N`, `GET /api/teacher/classes/{classId}/students` (full class roster — not just the top-5-by-activity list `GET /api/teacher/activity` returns) — requires Teacher or SchoolAdmin JWT; `GET/POST /api/teacher/classes/{classId}/join-code[/regenerate]` — Teacher role only, manages that class's student-facing join code
- School admin HTTP endpoints: `GET /api/admin/classes`, `POST /api/admin/classes` (now requires a `subjectId` tag), `GET /api/admin/classes/{classId}` (roster + teacher-assignment detail), `PUT /api/admin/classes/{classId}` (rename/retag), `PUT /api/admin/classes/{classId}/homeroom`, `DELETE /api/admin/classes/{classId}/students/{userId}` (removes one specific class membership — a student may belong to several; there is no corresponding POST to add one — a SchoolAdmin can no longer assign a student to a class directly, only the student's own `ClassJoinCode` self-join does that), `POST /api/admin/classes/{classId}/teachers`, `DELETE /api/admin/classes/{classId}/teachers/{teacherId}/subjects/{subjectId}`, `GET/POST /api/admin/subjects`, `POST /api/admin/teachers/{teacherId}/subjects/{subjectId}`, `DELETE /api/admin/teachers/{teacherId}/subjects/{subjectId}`, `GET /api/admin/users` (each user's `classNames` is now a list, not a single nullable name) — requires SchoolAdmin JWT
- Global admin HTTP endpoints: `POST /api/global-admin/schools`, `GET /api/global-admin/users`, `GET /api/global-admin/classes`, `POST /api/global-admin/classes` (now requires a `subjectId` tag, in addition to `schoolId`), `DELETE /api/global-admin/classes/{classId}`, `POST /api/global-admin/subjects`, `DELETE /api/global-admin/subjects/{subjectId}`, `POST /api/global-admin/classes/{classId}/students`, `POST /api/global-admin/classes/{classId}/teachers`, `PUT /api/global-admin/users/{userId}/role` — requires Admin JWT; endpoints that target a school accept `schoolId: int` (not a school name string). Unlike the SchoolAdmin surface, `POST /api/global-admin/classes/{classId}/students` (`AdminUserService.AssignStudentToClassAsync`) still lets an Admin assign a student to a class directly
- Curriculum file management HTTP endpoints: `GET /api/global-admin/curriculum/grades/{grade}/files`, `POST /api/global-admin/curriculum/grades/{grade}/files` (multipart upload, 409 on duplicate), `PUT /api/global-admin/curriculum/grades/{grade}/files/{fileKey}` (replace/re-ingest), `DELETE /api/global-admin/curriculum/grades/{grade}/files/{fileKey}` — requires Admin JWT; curriculum is grade-wide, not school-specific
- Student HTTP endpoints: `POST /api/student/practice-questions`, `GET /api/student/weak-spots?days=N`, `GET /api/student/history?limit=N`, `POST /api/student/exam`, `GET/POST /api/student/classes` (list joined classes / self-join via a `ClassJoinCode`, rate-limited per-IP) — requires Student JWT
- AI response language: the tutor mirrors whatever language the student wrote their question in (chat answers, mock exams, practice questions) rather than defaulting to one fixed language, independent of the UI's English copy — the question/topic's language is identified by `LanguageDetectionService.cs` (offline n-gram detection, with a Cyrillic-script short-circuit since inference-only instructions were unreliable, especially for short exam topics) and named explicitly in the system prompt built by `RAGService.cs`, `ExamService.cs`, and `PracticeQuestionService.cs` (see `CLAUDE.md`'s Language Policy section). Verified reliable for chat answers and practice-question generation; mock exam generation (`POST /api/student/exam`) inconsistently drifted to English (or, once observed, Chinese) with the previously pinned `minicpm-v` model even with an explicit language instruction — see `CLAUDE.md`'s Language Policy section for the current status now that `Llm:OllamaModel` points to `todorov/bggpt`. ## Production Deployment Notes

**Reverse proxy (required):** `UseForwardedHeaders()` is active. You must restrict which proxies are trusted — edit the `ForwardedHeadersOptions` block in `Program.cs` and add your specific proxy IP(s) to `KnownProxies`. Without this, any client can spoof `X-Forwarded-For` to bypass IP-based rate limiting.

**HSTS:** `UseHsts()` is active. The first response to each browser instructs it to refuse all future HTTP connections to this domain. Ensure TLS is configured before deploying.

**SMTP (required):** Password reset codes are delivered via email. Supply `Smtp__Host`, `Smtp__Username`, `Smtp__Password`, and `Smtp__From` via environment variables. The app refuses to start if placeholders are detected.

**Secrets:** All config keys in `appsettings.json` hold placeholder strings. Supply real values via environment variables (`Jwt__Secret`, `ConnectionStrings__DefaultConnection`, `TeacherRegistrationCode`, `Cors__AllowedOrigins__0`, `Smtp__Host`, `Smtp__Username`, `Smtp__Password`, `Smtp__From`). The app refuses to start if placeholders are detected.
